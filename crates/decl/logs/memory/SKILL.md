# 记忆检索导航

你拥有持久记忆，组织为以下文件。**记忆是跨会话持久化的**——即使这是新对话的第一个问题，之前的记忆也已经存在。

---

## 一、references/ — 自身相关记忆

| 文件路径 | 内容 | 何时读取 |
|---------|------|---------|
| `references/SOUL.md` | 你的名字、角色、人格 | 用户问"你是谁""你叫什么""你的身份"时，**必须先读** |
| `references/USER.md` | 用户身份、背景、创业方向 | 用户问"我是谁""我们在做什么""项目方向"时 |
| `references/RULES.md` | 用户设定的强制性行为准则 | 涉及"规则""应该怎么""之前定的规矩"时 |
| `references/LESSON.md` | 过往犯错及纠正记录 | 涉及"上次""之前""教训""犯过什么错"时 |
| `references/PREFERENCE.md` | 用户偏好（格式、风格、方向） | 涉及输出格式、交互风格时 |

---

## 二、assets/ — 外部知识（四级渐进）

```
assets/
├── INDEX.md                       ← 全局描述 + 三列导航表格（名称|描述|路径）
└── {主题}/
    ├── INDEX.md                   ← 主题描述 + 三列导航表格（章节→章节INDEX）
    └── {章节}/
        ├── INDEX.md               ← 章节描述 + 三列导航表格（小节→小节文件）
        └── {小节}.md              ← 完整知识内容（`# 标题` + 正文，无 frontmatter）
```

**渐进检索步骤：**
1. 读 `assets/INDEX.md` → 获取主题列表
2. 读 `assets/{主题}/INDEX.md` → 定位章节
3. 读 `assets/{章节}/INDEX.md` → 定位小节
4. 读 `assets/{章节}/{小节}.md` → 获取完整知识

**INDEX 为空或滞后时：** 勿断言「知识库为空」。记忆写回在后台异步完成——可说明「索引可能正在更新」，或稍后重读 INDEX。也可直接尝试读取已知章节目录。

## 三、决策强制触发器

| 问题类别 | 示例问法 | 必须读取 |
|---------|---------|---------|
| 你的身份 | "你是谁" | `references/SOUL.md` |
| 用户身份 | "我是谁" | `references/USER.md` |
| 目标方向 | "我们在做什么" | `references/USER.md` |
| 行为规则 | "之前定的规矩" | `references/RULES.md` |
| 过往经验 | "上次教训" | `references/LESSON.md` |
| 专业知识 | 已学习过的技术资料 | `assets/INDEX.md` 起渐进检索 |

不确定时 **先查再说**。

> **决策链**：`身份/用户/规则/教训/偏好 → references/ 直达；领域知识 → assets/INDEX.md 渐进检索`

## 四、检索流程

1. 判断问题类别 → 确定是否需查、查哪个文件
2. 若未加载本导航，先 `load_skill("skill-memory")`
3. 读取对应记忆文件
4. 基于记忆内容回答

**每会话每文件只读一次**——结果已在对话历史中则复用。**例外**：用户明确要求重新检查，或文件可能已被并发会话更新时允许重读。

### 文件读取失败

若记忆文件无法读取（损坏、不存在、权限不足）：

1. 如实说明存在记忆缺口，**不得**凭空编造内容
2. 尝试读取父级 INDEX 文件，获取可用目录信息作为备选
3. 建议用户稍后重试——记忆写回是后台异步完成的，文件可能正在更新中

### 归档文件跳过

`references/` 和 `assets/` 下可能存在 `*.archived.md` 文件，用于存放已废弃的历史版本。

- **正常检索时**：只读 `.md` 文件（不含 `.archived.md` 后缀），跳过归档文件
- **调查历史时**：用户明确问「之前的版本」「什么时候改的」「为什么改了」时，才读取对应的 `.archived.md` 文件
- INDEX.md 中的导航条目只指向 `.md` 文件，归档文件不出现在索引中

## 五、反例：常见错误行为

| 用户问 | 错误行为 | 正确行为 |
|--------|---------|---------|
| "你是谁" | 用训练数据默认身份 | 先读 `references/SOUL.md` |
| "我是谁"（新会话） | "第一次对话不知道" | 读 `references/USER.md` |
| `assets/INDEX.md` 为空 | "知识库还是空的" | 勿断言；后台可能正在沉淀；可重试或查子目录 |
| 用户要求记录知识 | 索要「是否可以录入」许可 | 在对话中结构化表达知识即可；写回由后台自动处理 |
| 第N轮重复问题 | 再次读取已读文件 | 复用对话历史中的结果 |

---

## 六、总则

1. **先读后答**：涉及触发类别时先读文件再回答。
2. **记忆跨会话持久化**：新会话不等于空白。
3. **每文件每会话只读一次**：结果已在对话历史中则复用；用户明确要求重查或文件可能被并发更新时例外。
4. **用户优先**：冲突时以用户最新表达为准。
5. **不知道就承认**：查了但为空，如实说明。
6. **跳过归档**：正常检索只读 `.md` 文件，`.archived.md` 仅在调查历史时读取。

---

## 七、写回记忆

记忆的写入和更新由**后台自动处理**。

你只需要在对话中**结构化表达**需要记住的信息（身份、偏好、学习成果、领域知识等）。

**禁止**向用户索要「是否可以录入」「结构是否可以」——表达即触发，无需用户批准写文件操作。
